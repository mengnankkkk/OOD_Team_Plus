# 资产多 Agent 深度报告生成设计

## 1. 目标

在资产页面为用户提供明确的“生成深度报告”入口。系统基于用户当前持仓、最新可用行情、财务画像和投资目标运行现有理财顾问多 Agent，生成可追溯的 Markdown 资产报告，并同步保留对应对话记录。

成功标准：

- 用户无需先执行查数或手工创建对话，即可从资产页发起报告生成。
- 每次报告生成创建独立对话，保存用户请求、Agent 回复和运行记录。
- 产物正文保存 Agent 撰写的完整报告，而不是仅保存持仓数据表。
- 报告完成后自动出现在资产页产物库中并打开预览。
- 行情降级、信息缺失、合规阻止和 Agent 失败均有明确状态，不产生虚假成功或空报告。

## 2. 非目标

- 不在本次实现 PDF、Word 或邮件导出。
- 不增加定时报告和自动推送。
- 不允许报告生成直接执行真实交易。
- 不重写现有多 Agent 专业分析体系。
- 不重构现有产物预览、版本修改和软删除功能。

## 3. 用户体验

### 3.1 生成入口

资产页“报告产物”标题右侧增加“生成深度报告”按钮。

按钮状态：

- 无持仓：禁用，并提示先录入持仓。
- 可生成：正常显示。
- 任务运行中：显示“Agent 分析中”，禁止重复点击。
- 最近任务失败：保留“重新生成”入口。

### 3.2 生成弹窗

弹窗展示：

- 报告范围：全部持仓，首版不可修改。
- 当前持仓数量。
- 最新组合快照时间和行情质量。
- 可选关注点，最多 500 字，例如“重点分析行业集中度和最大回撤”。
- “开始生成”和“取消”操作。

### 3.3 进度反馈

任务启动后在产物区域展示阶段进度：

1. 读取用户画像与目标。
2. 更新或确认最新行情。
3. 分析持仓和组合风险。
4. 执行压力测试。
5. 汇总支持证据与反方证据。
6. 进行合规复核。
7. 撰写并保存报告。

进度优先复用现有 Agent SSE 事件；前端不根据固定计时器伪造阶段。

### 3.4 完成状态

任务完成后：

- 自动重新加载产物列表。
- 自动选中新报告并打开预览。
- 展示“查看对应对话”入口。
- 报告列表显示报告时间、数据时间、状态和版本号。

每次报告生成创建独立对话，标题格式为：

`资产深度报告 · YYYY-MM-DD HH:mm`

## 4. API 设计

### 4.1 创建报告

`POST /api/v1/portfolio-reports`

请求：

```json
{
  "focus": "重点分析行业集中度和最大回撤",
  "forceRefresh": true
}
```

约束：

- `focus` 可选，最大 500 字。
- `forceRefresh` 默认 `true`。
- 必须携带 `Idempotency-Key`。
- 用户必须已登录。

响应状态为 `202`：

```json
{
  "data": {
    "conversationId": "conversation_xxx",
    "analysis": {
      "analysisId": "analysis_xxx",
      "type": "PORTFOLIO_REPORT",
      "status": "RUNNING",
      "streamUrl": "/api/v1/analyses/analysis_xxx/events"
    }
  }
}
```

接口只负责完成校验、创建独立对话并启动 Agent。报告和产物异步完成。

### 4.2 获取完成结果

复用现有分析详情和 SSE 接口。

完成后的 `agent_runs.result_json` 至少包含：

```json
{
  "conversationId": "conversation_xxx",
  "assistantMessageId": "message_xxx",
  "artifact": {
    "artifactId": "artifact_xxx",
    "status": "READY",
    "previewUrl": "/api/v1/generated-artifacts/artifact_xxx/preview"
  },
  "dataQuality": "COMPLETE"
}
```

前端收到完成事件后重新请求产物列表，不自行拼装产物内容。

## 5. 后端架构

### 5.1 PortfolioReportService

新增资产报告编排服务，职责如下：

1. 验证用户存在活动持仓。
2. 获取当前用户画像、目标和最近组合快照。
3. 在 `forceRefresh=true` 时尝试刷新行情。
4. 创建独立对话。
5. 构建服务端报告提示词。
6. 以 `FINANCIAL_REPORT` 输出模式启动现有对话多 Agent。
7. 将分析任务、对话和最终产物建立关联。

服务端生成提示词，前端只传递关注点。提示词必须要求：

- 基于当前用户的真实持仓和目标。
- 区分事实、推断和建议。
- 提供支持证据和反方证据。
- 报告中展示行情时间与数据质量。
- 不把研究模拟描述为真实交易指令。

### 5.2 多 Agent 复用

复用现有角色：

- `PROFILE_CONTEXT`
- `DATA_RESEARCH`
- `PORTFOLIO_RISK`
- `RECOMMENDATION`
- `COMPLIANCE_REVIEWER`
- `EXPLANATION_REPORT`

报告任务使用组合诊断意图。画像或目标不完整时：

- 允许生成组合诊断。
- 将个性化建议状态降级。
- 不输出具体个股买卖比例或确定性交易指令。
- 在报告中列出缺失信息。

### 5.3 对话持久化

每次报告使用独立 `conversation_sessions` 记录。

对话内容至少包含：

- 用户消息：系统根据用户操作生成的“请基于当前资产生成深度报告”，并追加用户关注点。
- Agent 回复：完整报告正文。
- 消息元数据：报告类型、组合快照 ID、行情质量和产物 ID。

用户在理财顾问页面中可以继续追问该报告。

## 6. 产物生成

### 6.1 正文来源

扩展产物创建服务，使 Markdown 产物可以接收经过安全清洗的 Agent 正文。

`FINANCIAL_REPORT` 产物正文组成：

1. Agent 完整报告正文。
2. 结构化持仓明细附录。
3. 数据来源和行情时间。
4. Agent 运行与证据溯源信息。
5. 投资研究免责声明。

现有根据行列自动生成 Markdown 表格的逻辑继续保留，用于查数结果产物；不得用该表格逻辑覆盖 Agent 报告正文。

### 6.2 产物关联

生成的 `generated_artifacts` 记录必须关联：

- 当前用户。
- 独立报告对话。
- Agent 回复消息。
- Agent 运行记录。
- 组合快照和数据来源信息。

不新增重复的报告存储表。

## 7. 报告结构

报告至少包含：

1. 执行摘要。
2. 数据快照与质量说明。
3. 总资产、浮盈亏和健康评分。
4. 单个持仓诊断。
5. 资产类别和行业配置。
6. 集中度与最大回撤。
7. 压力测试。
8. 支持证据、反方证据和 Agent 分歧。
9. 持有、观察、停止加仓、减仓或再平衡建议。
10. 建议触发条件、失效条件和观察期限。
11. 后续观察清单。
12. 持仓明细与数据来源附录。
13. 免责声明。

## 8. 异常和降级

### 8.1 无持仓

返回 `422 PORTFOLIO_EMPTY`，不创建对话和 Agent 任务。

### 8.2 行情刷新失败

如果存在最近有效组合快照：

- 继续生成报告。
- 将数据质量标记为 `DEGRADED`。
- 报告顶部明确展示行情时间和失败来源。

如果不存在任何有效行情快照：

- 返回失败状态。
- 保留已创建的运行记录。
- 不创建报告产物。

### 8.3 画像或目标不完整

继续生成组合风险诊断，将个性化建议降级，并列出缺失字段。

### 8.4 合规阻止

生成风险提示报告，但移除具体买卖动作、目标仓位和价格指令。

### 8.5 Agent 失败

- `agent_runs` 标记为失败并保存错误码。
- 保留对应对话和失败状态。
- 不创建空白产物。
- 前端提供重新生成入口。

### 8.6 重复请求

相同用户和相同 `Idempotency-Key` 返回同一个任务结果，不重复创建对话、消息或产物。

## 9. 前端组件

### 9.1 GeneratePortfolioReportDialog

负责：

- 展示快照摘要。
- 收集关注点。
- 发起报告任务。
- 展示请求错误。

### 9.2 PortfolioReportProgress

负责：

- 消费 SSE 进度。
- 展示真实 Agent 阶段。
- 在失败时提供重试。
- 在成功时返回产物 ID。

### 9.3 ArtifactLibrary

新增可选能力：

- 接收生成入口或标题操作区。
- 任务完成后重新加载列表。
- 根据新产物 ID 自动选中。
- 报告项展示对应对话入口。

现有预览、修改、删除功能保持兼容。

## 10. 安全与合规

- 所有持仓、对话、分析和产物查询必须按当前用户隔离。
- 前端不能提交任意用户 ID、组合快照 ID或消息 ID。
- 报告正文必须经过 Markdown 安全清洗。
- 产物中不得包含密钥、认证信息或原始内部提示词。
- 报告必须显示研究模拟免责声明。
- 失败日志不得返回 PandaData 凭证或模型密钥。

## 11. 测试与验收

### 11.1 后端测试

- 无持仓返回 `PORTFOLIO_EMPTY`。
- 正常请求创建独立对话和运行任务。
- 多 Agent 完成后创建用户消息、Agent 回复和 Markdown 产物。
- Markdown 正文包含 Agent 分析内容，不仅是持仓表格。
- 行情失败但存在快照时生成降级报告。
- 无有效快照时不生成空产物。
- 画像不完整时不输出个性化交易指令。
- 合规阻止时只生成风险提示。
- 相同幂等键不会创建重复记录。
- 用户不能读取其他用户的报告。

### 11.2 前端测试

- 无持仓时生成按钮不可用。
- 桌面端和移动端均可打开生成弹窗。
- 关注点可以提交且有长度校验。
- 运行中展示 Agent 进度并阻止重复点击。
- 完成后自动选中新产物。
- 报告可以跳转到对应对话。
- 失败后显示错误并支持重新生成。

### 11.3 端到端验收

完整流程：

1. 用户存在画像、目标和持仓。
2. 在资产页点击“生成深度报告”。
3. 输入关注点并提交。
4. 页面展示多 Agent 执行进度。
5. 报告生成完成并自动打开。
6. 报告包含组合数据、证据、风险、建议和免责声明。
7. 理财顾问历史中出现独立报告对话。
8. 用户可以进入对话继续追问。
